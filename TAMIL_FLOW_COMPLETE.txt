THE PROBLEM:
------------
• User clicks Tamil (தமி) button
• Types message (even simple text like "del")
• Gets response in ENGLISH instead of Tamil
• Entire flow stays in English

ROOT CAUSE:
-----------
Language detection was OVERRIDING the explicit UI selection!

Old logic:
  detected_lang = detect_from_text(message)  # Always ran first
  if detected_lang:
      language = detected_lang  # ❌ Overwrites UI choice!

Result: User selects Tamil → types "del" → detection fails → resets to English

THE FIX:
--------
Changed language priority in receptionist.py (lines 419-439):

NEW PRIORITY:
  1. UI Selection (highest) ← User explicitly chose Tamil/Hindi
  2. Stored Preference ← Remembered from previous messages  
  3. Text Detection ← Only if no explicit choice
  4. Default English ← Last resort

Fixed code:
  if language in ("ta", "hi", "en"):
      # User EXPLICITLY selected - RESPECT IT!
      use_language = language
  elif stored_preference:
      use_language = stored_preference
  else:
      use_language = detect_from_text()

✅ Click Hindi → Get Hindi responses (always!)  
✅ Switch mid-flow → Language changes immediately
✅ Preference persists → Stays in chosen language
